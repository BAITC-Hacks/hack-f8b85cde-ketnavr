# Ketnavr — рекомендации по закупкам

Приложение рассчитывает предложения по пополнению склада для ИЭК и SystemElectric на основе Excel-выгрузок. Менеджер видит рекомендуемое количество, срочность, остаток, товар в пути и объяснение. Список можно фильтровать и скачать в CSV или XLSX. **Заказы поставщикам приложение не отправляет.**

Проект состоит из FastAPI-сервиса (`backend/`) и интерфейса React + Vite (`frontend/`). Числовой расчёт выполняется в Python. Подключение AI необязательно: модель может переформулировать объяснения, но не определяет количество к заказу.

## Перед запуском

- Нужны Python и Node.js 22+ с npm.
- Нужен архив `Excel_IEK_Systeme_Electric_оформленные.zip` с папками `IEK/` и `Systeme electric/` внутри. Данные не входят в архив проекта.
- API-ключ для первого запуска не нужен: режим `template` создаёт объяснения по шаблону.

Ниже приведены команды для PowerShell в Windows. Начинайте из корня распакованного проекта.

## Быстрый запуск

### 1. Backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `backend/.env` и укажите **абсолютный путь** к архиву Excel вместо пути из примера. Пример настроек:

```env
DATA_ZIP_PATH=C:\Users\YourName\Downloads\Excel_IEK_Systeme_Electric_оформленные.zip
AS_OF_DATE=2026-09-22
AI_PROVIDER=template
```

`AS_OF_DATE` — дата расчёта; она не обновляется автоматически. Из каталога `backend` запустите:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Оставьте терминал открытым. В новом окне проверьте:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/data/summary
Invoke-RestMethod 'http://127.0.0.1:8000/recommendations?limit=5&ai=false'
```

Поле `data_zip_exists` в ответе `/health` должно быть `true`. Если оно `false`, проверьте `DATA_ZIP_PATH`. Интерактивная документация API: `http://127.0.0.1:8000/docs`.

### 2. Frontend

В другом PowerShell из корня проекта:

```powershell
cd frontend
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. При локальной разработке Vite направляет `/api/recommendations` на `http://127.0.0.1:8000/recommendations`. Кнопка **«Открыть демо»** показывает отдельно помеченные синтетические данные; они не получены из Excel.

## Настройки и API-ключи

В `backend/.env.example` перечислены все параметры:

| Параметр | Назначение |
| --- | --- |
| `DATA_ZIP_PATH` | Абсолютный путь к архиву исходных Excel. |
| `AS_OF_DATE` | Дата расчёта `YYYY-MM-DD`. |
| `MAX_RECOMMENDATIONS` | Максимум возвращаемых позиций, по умолчанию 120. |
| `SAFETY_STOCK_DAYS` | Дополнительные дни запаса, по умолчанию 14. |
| `IEK_LEAD_TIME_DAYS`, `SYSTEME_LEAD_TIME_DAYS` | Сроки поставки, по умолчанию 18 и 14 дней. |
| `AI_PROVIDER` | `template`, `openai`, `nvidia` или `auto`. |
| `AI_MAX_ROWS` | Число строк с объяснением от модели, по умолчанию 8. |

AI вызывается только из backend. Для NVIDIA добавьте в `backend/.env`:

```env
AI_PROVIDER=nvidia
NVIDIA_API_KEY=ваш_ключ
NVIDIA_MODEL=meta/llama-3.1-8b-instruct
```

Для OpenAI:

```env
AI_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-5.6-luna
```

`AI_PROVIDER=auto` пробует OpenAI, затем NVIDIA, если указаны оба ключа. При сбое внешнего API остаётся шаблонное объяснение. Адрес NVIDIA задаётся через `NVIDIA_BASE_URL` (по умолчанию `https://integrate.api.nvidia.com/v1`). `GET /ai/status` показывает наличие ключа, но не его значение. После изменения `.env` перезапустите backend.

**DigitalOcean пока не реализован как AI-провайдер в этом коде.** Его ключ не подходит для `NVIDIA_API_KEY` или `OPENAI_API_KEY`: нужна отдельная интеграция. Не сохраняйте реальные ключи в Git, коде frontend или переменных `VITE_*`, которые доступны браузеру.

Frontend обычно работает без дополнительной настройки. При необходимости используйте `frontend/.env.example`: `BACKEND_URL` задаёт цель dev proxy, `VITE_API_BASE_URL` и `VITE_RECOMMENDATIONS_PATH` — адрес браузерного запроса. После изменений перезапустите Vite.

## Метод расчёта

`backend/app/data_loader.py` считывает из ZIP для каждого поставщика MOQ, ежемесячные продажи, ежемесячные остатки и товар в пути. Позиции сопоставляются по коду 1С. Для расчёта берутся последние шесть доступных месяцев продаж на дату `AS_OF_DATE`:

1. Влияние разовых месячных пиков ограничивается по медиане и медианному абсолютному отклонению.
2. Среднемесячные продажи переводятся в дневной спрос. Тренд сравнивает последние три месяца с предыдущими тремя; коэффициент ограничен диапазоном 0,85–1,25.
3. Сезонный коэффициент следующего месяца рассчитывается из месячной истории при достаточном количестве наблюдений и ограничен диапазоном 0,8–1,2.
4. Потребность = прогнозный дневной спрос × (срок поставки + дни страхового запаса) − (остаток + товар в пути). Положительная потребность округляется вверх до кратности MOQ.
5. Срочность `critical` означает покрытие меньше срока поставки, `soon` — меньше срока поставки со страховым запасом. Позиции с нулевой потребностью не возвращаются.

Результат сортируется по срочности и количеству, затем ограничивается `MAX_RECOMMENDATIONS`. Модель меняет лишь текст `reason` первых `AI_MAX_ROWS` строк. Параметр `?ai=false` отключает AI для запроса. Параметр `limit` принимает 0–500; значение 0 использует настройку по умолчанию.

### Ограничения прототипа

- Детальная динамика продаж и отдельные файлы сезонности есть в архиве, но загрузчик их **не читает**. Сезонность выводится из ежемесячных продаж; крупные заказы одного клиента не выявляются.
- Периоды отсутствия товара на складе и упущенный спрос отдельно не учитываются.
- Срок поставки задаётся для поставщика в целом. Если положительное MOQ не прочитано, используется кратность 1.
- Загруженный ZIP кэшируется в процессе по пути и срокам поставки. После замены файла по тому же пути перезапустите backend.
- Подтверждение и отправка заказа в учётную систему не реализованы. Рекомендации требуют проверки менеджером.

Это существенные отличия от полного задания кейса по stockout и клиентским выбросам.

## API, экспорт и проверка

| Запрос | Что возвращает |
| --- | --- |
| `GET /health` | Состояние сервиса и наличие архива. |
| `GET /data/summary` | Сводку по загруженным товарам и поставщикам. |
| `GET /ai/status` | Настройку AI без раскрытия ключа. |
| `GET /recommendations` | Рекомендации в JSON с `schema_version: "1.0"`. |

Frontend фильтрует и сортирует строки в браузере. CSV и XLSX выгружаются из **текущей видимой выборки**; серверного endpoint экспорта нет. Демо-выгрузки имеют префикс `DEMO-`. Формат ответа проверяет `frontend/src/lib/contract.js`.

`outputs/API_CONTRACT.md` описывает поля ответа, однако его вступление было написано до появления backend. Для текущих маршрутов и параметров используйте `backend/app/main.py` и `/docs`.

Проверки из соответствующих каталогов:

```powershell
# backend/
.\.venv\Scripts\python.exe -m unittest discover -s tests

# frontend/
npm test
npm run build
```

Для публикации frontend нужен маршрут `/api` к backend либо публичный `VITE_API_BASE_URL` и соответствующий CORS. Dev proxy Vite не входит в production-сборку; текущий backend разрешает CORS только для локального frontend.
