# Проверка Ketnavr — 23.09.2026

## Область проверки

Проверен frontend по согласованному сценарию команды: реальный API → таблица → фильтры → карточка товара → CSV/XLSX. Backend, его расчёт и README не изменялись. Официальный файл критериев закупочного трека и исходные Excel-архивы в рабочей папке недоступны, поэтому этот отчёт **не подтверждает соответствие всем критериям жюри или точность исходного расчёта по Excel**.

Проверка проведена через локальный Vite на порту 5173 и подключённый сохранённый снимок backend с датой данных 22.09.2026. Искусственные сбои проверялись на отдельном локальном сервере 5174, без вмешательства в рабочий backend.

## Исправления

- «Порядок backend» переименован в «Рекомендуемый порядок». Значение сортировки и порядок API сохранены. Сортировка по умолчанию остаётся «По приоритету».
- «Запас на складе» в карточке заменён на «Покрытие с учётом пути»; колонка таблицы — «Покрытие, дн.»; аналогичная подпись добавлена в CSV/XLSX. Числа не пересчитываются на frontend.
- На экране ошибки доступно скачивание `back-front-errors.json`: последние 25 записей с временем, причиной и контекстом запроса. При недоступном или повреждённом localStorage используется память вкладки. На экране остаётся короткое «Ошибка при загрузке данных».

## Ограничения и что нужно для защиты

1. **Не называть частичную сумму полным бюджетом.** Для полного итога нужны отсутствующие цены от источника данных.
2. **Не утверждать, что все объяснения сгенерированы OpenAI.** В текущем снимке ИИ обогатил 3 позиции; остальные объяснения шаблонные. Найдено 156 различных текстов на 221 строку. Контракт не содержит `reason_source`, поэтому frontend не угадывает источник каждого текста.
3. **«Планово» сейчас может давать пустую выборку.** Endpoint возвращает товары к заказу, а не полный ассортимент, включая нулевую потребность.
4. **Снимок не пересчитывается кнопкой «Обновить».** Она перечитывает опубликованный результат. Дата среза видна на странице.
5. **Временная общая ссылка зависит от ноутбука и туннеля backend.** Для стабильного размещения нужны постоянный сервер и production-proxy `/api` либо согласованный CORS. Vite dev proxy не переносится в статическую сборку.
6. **Не проверены исходные Excel, точность прогноза/сезонности и все физические единицы.** API сейчас передаёт `шт.` у всех строк; для труб и других товаров владелец данных должен подтвердить единицы. UI выводит переданное значение.
7. Это функциональная приёмка frontend, не полноценный аудит безопасности, нагрузочное тестирование или проверка всех браузеров/ассистивных технологий.

## Повторение проверки

Из `frontend`:

```powershell
npm test
npm run build
node tests/live-check.mjs
```

`live-check.mjs` — явная проверка текущего согласованного снимка 221/177/44 через работающий локальный proxy 5173. Контрольные числа не используются в UI. При обновлении исходных данных ожидания теста нужно пересмотреть с backend.

Изолированные UI-сценарии:

```powershell
node tests/qa-server.mjs
```

Только localhost:5174; сценарий выбирается POST-запросом `/__qa/scenario` с текстом `error`, `invalid`, `empty`, `ready` или `slow`, затем нажатием «Повторить»/«Обновить». `ready` использует явно синтетическую фикстуру. Этот сервер не входит в production и не обращается к рабочему backend.
