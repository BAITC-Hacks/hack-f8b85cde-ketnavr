# Контракт frontend ↔ backend, версия 1.0

Контракт используется подключённым frontend и backend. Адаптация ответа сосредоточена в `frontend/src/lib/contract.js`, запрос — в `frontend/src/lib/api.js`. Фронтенд не пересчитывает потребность и не назначает срочность.

## Endpoint

`GET /recommendations` → `200 application/json`.

По умолчанию endpoint возвращает позиции к заказу. `include_no_order=true`
добавляет рассчитанные товары с достаточным запасом и заказом `0`.
`limit=0` снимает ограничение числа строк; положительный `limit` ограничивает ответ.
`ai=false` отключает внешнее обогащение объяснений в основном backend.

Frontend запрашивает `include_no_order=true&limit=0` и локально переключается
между «К закупке» и «Весь расчёт». Выбор «Планово» включает полный расчёт.
Строки без достаточной истории спроса не подменяются статусом `normal` и пока
не входят в этот endpoint. Пагинации на сервере нет: frontend показывает по 50 строк,
но сводка и экспорт учитывают всю отфильтрованную выборку. Количества, срочность
и объяснения не пересчитываются на фронте.

```json
{
  "schema_version": "1.0",
  "as_of": "2026-09-22",
  "recommendations": [
    {
      "id": "SE-DEMO-001",
      "sku": "SE-DEMO-001",
      "product_name": "Автоматический выключатель 1P 16A",
      "supplier": "SystemElectric",
      "category": "Автоматика",
      "unit": "шт.",
      "stock_qty": 18,
      "in_transit_qty": 0,
      "recommended_order_qty": 120,
      "urgency": "critical",
      "reason": "Остатка хватит на 3 дня при спросе 6 шт./день, а поставка занимает 14 дней. Рекомендовано 120 шт. с учётом MOQ 12 шт.",
      "avg_daily_demand": 6,
      "coverage_days": 3,
      "lead_time_days": 14,
      "moq": 12,
      "unit_price_kzt": 2150,
      "synthetic": true
    }
  ]
}
```

Пример выше синтетический. Значения не рассчитаны из пользовательских Excel-файлов.

## Поля

| Поле | Тип | Правило |
|---|---|---|
| schema_version | string | Ровно `1.0` |
| as_of | string | Реальная дата среза данных, YYYY-MM-DD |
| recommendations | array | Все позиции расчёта; `[]` — корректный пустой результат |
| id | string | Уникальный стабильный ID строки; не просто номер строки |
| sku, product_name, supplier, category, reason | string | Непустые строки |
| stock_qty, in_transit_qty, recommended_order_qty | number | Обязательные конечные числа ≥ 0, не строки; дробные значения разрешены |
| urgency | string | `critical`, `soon`, `normal` — решение backend |
| unit | string | Необязательное, по умолчанию `шт.` |
| avg_daily_demand, coverage_days, lead_time_days, moq, unit_price_kzt | number/null | Необязательные конечные числа ≥ 0; отсутствие означает «не передано», а не ноль |
| synthetic | boolean | Необязательное, по умолчанию false; true показывает явную отметку синтетики |

`coverage_days` — покрытие складским остатком вместе с количеством в пути,
делёнными на прогнозный дневной спрос, округлённое backend. Это не обещанная
дата фактического поступления. `normal` в реальном расчёте означает,
что дополнительный заказ сейчас не требуется, `recommended_order_qty=0`.
Все количественные поля одной строки используют одну единицу измерения.
Цена `unit_price_kzt` — закупочная цена за эту единицу, не сумма строки.
Итог на фронте = сумма `recommended_order_qty × unit_price_kzt` для товаров к заказу;
при неизвестных ценах итог явно помечается как неполный. Общий объём в штуках
не суммируется, поскольку единицы разных строк могут отличаться.

«Рекомендуемый порядок» сохраняет порядок API; «По приоритету» сортирует по срочности, затем ID; «По количеству к заказу» — по убыванию количества, затем ID. Сортировки меняют только представление, не количества или объяснения.

Если backend пока не умеет поле optional, передавайте null или опускайте его. Не заполняйте недостающие цены нулями. Профили SystemElectric/ИЭК не зашиты в фильтры: варианты строятся из ответа.

## Локальное подключение

1. Backend слушает `http://127.0.0.1:8000` и возвращает JSON на `/recommendations`.
2. Frontend слушает `http://127.0.0.1:5173` и вызывает `/api/recommendations`.
3. Vite proxy убирает `/api` и передаёт запрос backend. CORS для такого локального режима не нужен.
4. Если backend уже использует путь `/api/recommendations`, задайте `VITE_RECOMMENDATIONS_PATH=/api/recommendations`: frontend запросит `/api/api/recommendations`, а proxy удалит только первый `/api`.

`frontend/.env.example` содержит все настройки. После изменения `.env` перезапустите Vite.

Для опубликованного frontend нужен reverse proxy `/api` или `VITE_API_BASE_URL=https://адрес-backend` и разрешённый CORS на backend. Vite dev proxy не входит в production-сборку. API-ключи NVIDIA и другие секреты нельзя класть в `VITE_*`, исходный код frontend или ответ API.

## Ошибки и состояния

- `200` + пустой массив → «Расчёт пока без рекомендаций».
- Есть строки, но фильтры скрыли все → «Нет товаров по этим фильтрам».
- Не-2xx, HTML вместо JSON, неверная схема, таймаут 45 с, сетевой сбой → «Ошибка при загрузке данных» с кнопкой повтора.
- Технические ошибки сохраняются в журнале `back-front-errors` (последние 25 записей); если localStorage недоступен, журнал хранится в памяти вкладки. Кнопка на экране ошибки скачивает `back-front-errors.json`. Автоматической записи в произвольную папку пользователя нет.
- Автоматического переключения на демо при ошибке нет.
- Повторный запрос — чтение текущего расчёта. Запуска расчёта и отправки заказа поставщику на фронте нет.
- При переключении источника старый запрос отменяется; данные разных источников не смешиваются.

## ИИ-помощник

`POST /assistant/chat` (через Vite и сервер показа: `/api/assistant/chat`).
Тело JSON: `{ "question": "Почему нужен заказ?", "history": [] }`.
Ответ: `{ "answer": "Текст объяснения" }`.

- Вопрос: 1–1000 символов, не пустой после удаления пробелов.
- История: до 10 объектов `{ "role": "user" | "assistant", "content": "..." }`,
  по 1–1500 символов; frontend обрезает длинные предыдущие ответы до этого лимита.
- Ответ: до 4000 символов, выводится как текст, не HTML.
- Таймаут frontend: 30 секунд, без автоматического повтора платного запроса.
- `422` — неверный запрос; `429` — частота/параллельность; `503` — чат выключен,
  нет провайдера или данных; `502` — ошибка провайдера/чтения данных.
- На основном backend нужен настроенный провайдер; на `app.share` дополнительно
  требуется `SHARE_CHAT_ENABLED=true` и перезапуск (см. `SHARING.md`).
- Лимит процесса: 10 запросов за 60 секунд, максимум 2 одновременно.
- Сводка строится по всему расчёту, а не фильтрам браузера; модели передаются
  только до 18 подобранных строк. На общем сайте используется сохранённый снимок,
  локально — текущий расчёт из данных backend. Количества/статусы не изменяются.
- История диалога живёт в памяти вкладки и сбрасывается при смене API/демо.
  В демо и до загрузки данных отправка отключена. При сбое вопрос остаётся в поле.
- API-ключи не передаются фронту; вопрос, история и контекст передаются выбранному
  AI-провайдеру. Чат может расходовать токены и не предназначен для публичного
  использования без авторизации и контроля расходов.

## Демо и экспорт

В рабочем интерфейсе нет входа в демо. Для отдельной демонстрации задайте `VITE_DATA_MODE=demo` и перезапустите Vite или пересоберите frontend. `frontend/src/data/demo.js` проходит тот же валидатор, что и API. Баннер и выгрузки явно помечены как синтетические; кнопка «К рабочим данным» возвращает API. После перезагрузки источник снова определяется настройкой сборки.

CSV и настоящий XLSX генерируются в браузере из текущей отфильтрованной и отсортированной выборки; серверный endpoint экспорта не требуется. Оба файла содержат объяснения, дату среза и источник. CSV — UTF-8 с BOM, разделитель `;`, экранирование кавычек и защита от формул. В XLSX количества сохраняются числами. Демо-файлы имеют префикс `DEMO-`.
