# Проверка пагинации, 23.09.2026

## Исправление

Таблица ограничена по высоте и прокручивается внутри своей области. Если
страниц несколько, высота области постоянна, включая последнюю неполную
страницу. Заголовки колонок закреплены. Переход между страницами сбрасывает
только вертикальную прокрутку таблицы, сохраняя её горизонтальную позицию.
Положение окна не зависит от числа строк и длины названий товаров.

Подпись сортировки: «Рекомендуемый порядок». Значение `original` и порядок
данных API не изменены. Экспорт по-прежнему включает всю отфильтрованную
выборку, а не одну страницу.

## Проверено

- Реальный снимок от 22.09.2026: фильтр «Критично», 177 товаров, четыре страницы.
- Страницы 1–3 содержат по 50 строк, страница 4 содержит 27 строк.
- Переходы 2 → 3 и 3 → 4: положение окна и панели пагинации не изменилось.
- Проверены размеры 390 × 844 и 1440 × 960, а также обычная панель браузера.
- На мобильном экране переходы 4 → 3 → 2 также сохраняют положение окна.
- Горизонтальная позиция таблицы сохранилась при переходе: 40 px до и после.
- Заголовки, стрелки и сортировка видны без перекрытия элементов.
- `npm test`: 21 тест пройден, включая разбиение 177 критичных строк без потерь.
- `npm run build`: успешно; предупреждение о размере ExcelJS остаётся прежним.

## Повторить в браузере

1. Обновить страницу и выбрать «Критично».
2. Последовательно перейти на страницы 2, 3 и 4, затем вернуться назад.
3. Проверить, что панель пагинации остаётся на месте, а таблица начинает
   новую страницу с первой строки, без прокрутки всего сайта наверх.
4. На узком экране прокрутить таблицу вправо и переключить страницу:
   горизонтальная позиция должна сохраниться.
5. Проверить название «Рекомендуемый порядок» в списке сортировки.
