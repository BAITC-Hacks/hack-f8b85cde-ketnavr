# Подключение frontend

## Текущее состояние

Backend больше не обрезает выдачу до первых 120 критичных позиций.
Формат JSON остался прежним, `schema_version` равен `1.0`.
Изменение backend: `7f16b63`. Новых ключей или API-библиотек на frontend не требуется.

Общая версия для проверки:
https://hotels-describe-dear-times.trycloudflare.com/

Это временный адрес. Он работает, пока на ноутбуке владельца запущены сервер
и Cloudflare-туннель и есть интернет. После нового запуска туннеля адрес может измениться.

## 1. Получить код

Из корня репозитория на ветке `main`:

```powershell
git pull --ff-only origin main
cd frontend
npm install
```

Если Git сообщает о конфликте или расхождении истории, сначала согласуйте
свои изменения с командой. Не используйте `reset --hard` или force push.

## 2. Подключить локальный frontend

В `frontend/.env.local` задайте:

```env
BACKEND_URL=https://hotels-describe-dear-times.trycloudflare.com
VITE_API_BASE_URL=/api
VITE_RECOMMENDATIONS_PATH=/recommendations?ai=true&limit=0
VITE_DATA_MODE=api
```

После изменения настроек перезапустите Vite из папки `frontend`:

```powershell
npm run dev
```

Откройте `http://127.0.0.1:5173/`. Если порт занят, используйте
`npm run dev -- --port 5174` и адрес из вывода команды.

Браузер обращается к локальному `/api`, а настроенный Vite proxy передаёт
запрос на `BACKEND_URL`. Не заменяйте `VITE_API_BASE_URL` на внешний адрес:
для этой схемы не требуется изменять CORS. Это настройка разработки;
для отдельного production-размещения нужен серверный proxy или общий origin.

## 3. API

Через локальный frontend: `GET /api/recommendations?ai=true&limit=0`.
На общей ссылке доступны тот же endpoint и `GET /api/health`.
Тело запроса, авторизация и ключ OpenAI на frontend не нужны.

Ответ содержит `schema_version`, `as_of`, `recommendations`.
Поля каждой рекомендации и их типы описаны в [контракте](outputs/API_CONTRACT.md).
Числа приходят числами; неизвестная цена равна `null`.
Используйте `id` как ключ строки. Не пересчитывайте количества и приоритеты во frontend.

`limit=0` означает полную выдачу позиций к заказу. Положительный `limit`
ограничивает список. Данные, где заказывать ничего не требуется, не входят в этот endpoint.
Не делайте `slice(0, 120)` на frontend. Существующие фильтры уже работают со всей выдачей.
Сохраните таймаут 45 секунд и явное сообщение при ошибке, без автоматической подмены демо.

## 4. Приёмочная проверка

Для текущего набора Excel и даты расчёта 22.09.2026 ожидается:

- Без фильтров: 221 позиция, из них 177 критичных.
- Поставщик «ИЭК»: 205 позиций.
- Поставщик «SystemElectric»: 16 позиций.
- Срочность «Заказать скоро»: 44 позиции.
- «SystemElectric» вместе с «Заказать скоро»: 8 позиций.
- Срочность «Планово»: пустая выборка допустима, так как здесь только товары к заказу.

Проверьте поиск, открытие карточки и CSV/Excel для отфильтрованной выборки.
Количество строк экспорта должно соответствовать фильтрам. Не подставляйте ноль вместо
неизвестной цены и не показывайте частичную сумму как полный бюджет заказа.
Если уже открытая общая страница показывает старые 120 строк, обновите её через `Ctrl+F5`.

Эти числа нужны только для проверки текущего набора, не фиксируйте их в UI или логике.

## 5. Как используется ИИ

Общая ссылка отдаёт сохранённый снимок. Для трёх позиций подготовлены объяснения
OpenAI, остальные используют расчётный шаблон. `ai=false` возвращает шаблоны для всех.
Обновление страницы общей версии не вызывает платный API и не перечитывает Excel.
За пересоздание снимка отвечает backend. Прямой основной backend с `ai=true`
может делать новые запросы к провайдеру.

Поля `reason_source` пока нет. Не помечайте все объяснения как OpenAI и не
определяйте источник по тексту. Для точных меток сначала согласуйте добавление
метаданных с backend. Не добавляйте ключи в JavaScript, `VITE_*` или Git.
Демо включается отдельно через `VITE_DATA_MODE=demo` и требует перезапуска или сборки.
