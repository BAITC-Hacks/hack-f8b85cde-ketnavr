# Запас — frontend рекомендаций по закупкам

React + Vite. Роль участника 3: показать результат расчёта backend, дать фильтры и выгрузить CSV / Excel.

## Запуск

Нужен Node.js 22+.

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Приложение сначала обращается к backend. Пока его нет, показывается понятная ошибка; кнопка **Открыть демо** включает отдельно помеченные синтетические данные. Это демонстрация интерфейса, а не результат обработки Excel.

## Подключение к backend

Предлагаемый контракт — [outputs/API_CONTRACT.md](outputs/API_CONTRACT.md). До согласования с бэкендером он не является подтверждённым API команды.

По умолчанию backend: `http://127.0.0.1:8000/recommendations`. Frontend вызывает `/api/recommendations`, а dev proxy удаляет `/api`.

При необходимости скопируйте `frontend/.env.example` в `frontend/.env` и настройте `BACKEND_URL`, `VITE_API_BASE_URL`, `VITE_RECOMMENDATIONS_PATH`. После изменения перезапустите frontend. Секреты не должны попадать в `VITE_*`.

Если backend возвращает другую схему, адаптируйте её в **одном месте** — `frontend/src/lib/contract.js`. Компоненты должны получать стабильную нормализованную структуру. Запросы и таймаут находятся в `frontend/src/lib/api.js`.

## Готовые возможности

- Поиск по наименованию / артикулу; фильтры по поставщику, категории и срочности.
- Таблица остатков, товара в пути, покрытия в днях и рекомендуемого заказа.
- Стабильная сортировка по приоритету или количеству; можно оставить исходный порядок backend.
- Сводка по текущей выборке, отдельная пометка суммы без неизвестных цен.
- Клик по товару открывает объяснение и исходные показатели; Escape закрывает диалог.
- Скачивание текущей выборки в CSV / настоящий `.xlsx` с датой, источником и объяснением.
- Загрузка, сбой API, невалидный ответ, пустой расчёт и пустая фильтрация — разные состояния.
- Мобильный интерфейс и горизонтальная прокрутка таблицы, клавиатурная навигация.
- Демо не подменяет ошибку API и не сохраняется скрыто в браузере.

Расчёты закупок, загрузка исходных Excel, генерация объяснений моделью и вызовы NVIDIA API относятся к backend и в этом frontend **не реализованы**. Расчётные значения демо вымышлены. Обновление читает результаты, не пересчитывает потребность и не отправляет заказы.

## Проверки и сборка

```powershell
cd frontend
npm test
npm run build
npm run preview
```

Тесты проверяют контракт, ошибки API без подмены моками, сочетание фильтров, стабильность сортировки, неизвестные цены, безопасный CSV и чтение созданного XLSX обратно.

Сборка лежит в `frontend/dist`. Для её публикации настройте reverse proxy `/api` на backend или задайте публичный `VITE_API_BASE_URL` перед сборкой и CORS на backend. Dev proxy Vite в production не работает.

## Структура

```text
frontend/
  src/App.jsx              интерфейс
  src/styles.css           адаптивная вёрстка
  src/lib/api.js           единственная точка HTTP-доступа
  src/lib/contract.js      проверка и нормализация ответа
  src/lib/data.js          фильтрация, сводка, отображение
  src/lib/export.js        CSV и Excel
  src/data/demo.js         явно синтетический пример
  tests/core.test.js       проверки интеграционной границы
outputs/API_CONTRACT.md    передать бэкендеру
```

## Первый командный push

Этот каталог изначально не был Git-репозиторием. Скопируйте `frontend/`, `outputs/API_CONTRACT.md` и нужные части README в командный репозиторий. Не коммитьте `node_modules/`, `dist/`, `.env` и `work/`. Рекомендуемое сообщение коммита: `frontend: procurement dashboard, API contract and Excel export`.
