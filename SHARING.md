# Временная общая ссылка

Сайт работает, пока включён ноутбук и запущены сервер показа и туннель.
Ссылка доступна через интернет, а не только в одной Wi-Fi-сети.

**Перед публикацией получите разрешение владельца данных.** Все, у кого есть
ссылка, смогут видеть и скачивать показанные товары, поставщиков, остатки,
цены и рекомендации к закупке. Трафик проходит через Cloudflare. Пароля здесь нет.
Исходный Excel-архив и API-ключи не публикуются.

## 1. Подготовка

Настройте и запустите backend по [QUICKSTART.md](QUICKSTART.md) на
`127.0.0.1:8000`. Ключи хранятся только в `backend/.env`.

Из корня проекта соберите frontend:

```powershell
cd frontend
npm install
$env:VITE_API_BASE_URL='/api'
$env:VITE_RECOMMENDATIONS_PATH='/recommendations?ai=true'
$env:VITE_DATA_MODE='api'
npm run build
Remove-Item Env:VITE_API_BASE_URL, Env:VITE_RECOMMENDATIONS_PATH, Env:VITE_DATA_MODE
```

Эти параметры применяются при сборке. В готовой версии не используется Vite proxy.

## 2. Сервер показа

В новом терминале из корня проекта:

```powershell
cd backend
.\.venv\Scripts\uvicorn app.share:app --host 127.0.0.1 --port 8010
```

Если backend работает по другому адресу, перед запуском задайте
`$env:SHARE_BACKEND_URL='http://127.0.0.1:8000'` с нужным адресом.

При старте сервер получает полный реальный расчёт (`limit=0&include_no_order=true`), затем
запрашивает объяснения ИИ для первых трёх строк. Этот стартовый запрос может
расходовать токены настроенного провайдера. Если ИИ недоступен, остаются
расчётные объяснения. Если backend недоступен, запуск завершается ошибкой,
а не подменяет данные демо.

Откройте `http://127.0.0.1:8010/`. Проверьте поиск, карточку товара и экспорт.
`http://127.0.0.1:8010/api/health` показывает дату снимка и число строк.
Параметр `ai=false` у `/api/recommendations` возвращает расчётные объяснения.
По умолчанию API отдаёт только товары к заказу; `include_no_order=true`
включает позиции с достаточным запасом. В статусе `recommendations` обозначает
число позиций к заказу, `calculated_products` обозначает весь расчёт.

Публичные GET-запросы рекомендаций читают только снимок в памяти. Числа вычисляет backend;
ИИ меняет только объяснения. Кнопка обновления не перечитывает Excel и не
вызывает ИИ. Для нового снимка перезапустите сервер показа (это снова может
расходовать токены). Встроенное демо остаётся отдельным режимом frontend.

### ИИ-помощник (необязательно)

Чат работает отдельно от обновления таблицы. На сервере показа он по умолчанию
выключен. Для включения в `backend/.env` задайте `SHARE_CHAT_ENABLED=true`,
настройте `AI_PROVIDER=openai`, `nvidia` или `auto` и соответствующий ключ.
Ключи остаются только на backend. После обновления кода пересоберите frontend
и перезапустите `app.share`; `/api/health` покажет `chat_enabled: true`.
Для отключения верните `SHARE_CHAT_ENABLED=false` и перезапустите сервер.

**Включайте только с разрешения владельца данных и API-ключа.** Каждый вопрос
может расходовать токены. Провайдеру передаются вопрос, до 10 сообщений истории,
сводка всего снимка и до 18 подходящих строк расчёта (в том числе остатки и цены).
При `AI_PROVIDER=auto` резервный провайдер может получить тот же контекст.
История хранится в памяти вкладки; собственное серверное хранилище чата не создаётся.

Все обладатели ссылки смогут пользоваться включённым чатом. Ограничение —
10 запросов за минуту и 2 одновременно на процесс; это не авторизация и не
денежный лимит. Для постоянного публичного продукта нужны авторизация и лимиты
расходов у провайдера. Не увеличивайте число процессов, рассчитывая на общий лимит.

Чат использует тот же снимок и дату, что таблица, но **весь расчёт, не текущие
фильтры**. Он не меняет приоритеты, количества и не отправляет заказы поставщикам.
Ограниченная выборка строк не позволяет гарантировать ответ о любом товаре;
точные значения сверяйте с карточкой и экспортом. Если провайдер не настроен или
недоступен, показывается ошибка, а не выдуманный ответ. Демо-режим не отправляет
сообщения ИИ. Обновление таблицы по-прежнему не вызывает платный чат.

## 3. Туннель

Только после согласия на публикацию данных используйте `cloudflared` из
[официального релиза Cloudflare](https://github.com/cloudflare/cloudflared/releases).
Например, если Windows-версия сохранена как `.tools/cloudflared.exe`,
в третьем терминале из корня проекта:

```powershell
.\.tools\cloudflared.exe tunnel --url http://127.0.0.1:8010 --protocol http2 --no-autoupdate
```

В выводе появится адрес `https://...trycloudflare.com`. Откройте именно его,
проверьте загрузку таблицы и передайте команде. При повторном запуске адрес
может измениться. Quick Tunnel предназначен для временной проверки и не
гарантирует доступность: [документация Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).

Не направляйте публичный туннель на Vite или основной backend с диагностическими
endpoint. Здесь публикуется только порт 8010: сборка frontend, рекомендации,
обезличенный статус и отдельно включаемый чат. Секреты, архив, `.tools` и `.share`
не добавляйте в Git.

## 4. Остановка

Нажмите `Ctrl+C` в терминале туннеля, чтобы закрыть внешний доступ, затем
`Ctrl+C` в терминале сервера показа. При необходимости остановите основной
backend отдельно. Отключение ноутбука тоже прерывает доступ по ссылке.
